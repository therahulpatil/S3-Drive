# ☁️ S3 CloudDrive - Secure AWS S3 Management System

A production-grade, Google Drive-style web application for managing AWS S3 Buckets and Access Point Aliases. Built with **React 18**, **Vite**, **Express.js**, **Tailwind/Vanilla CSS**, and **AWS SDK v3**.

---

## 🔒 Security Architecture

- **IAM Role Credentials (Recommended for EC2)**: Zero secret keys needed! When running on EC2 with an attached IAM Role, AWS SDK automatically fetches temporary credentials from the EC2 Instance Metadata Service (IMDSv2).
- **Server Proxy Credentials (Alternative)**: AWS Access Keys (`AWS_ACCESS_KEY_ID` & `AWS_SECRET_ACCESS_KEY`) are kept **100% server-side** inside `server.js` / `.env`.
- **Presigned URLs**: File uploads and downloads use short-lived temporary S3 Presigned URLs generated by the Node Express proxy server.
- **Git Secrets Protection**: [`.gitignore`](.gitignore) prevents `.env` and sensitive credentials from ever being committed or pushed to GitHub.

---

## ✨ Features

- 📁 **Folder & Object Management**: Create virtual directories, list contents, calculate folder sizes, and delete directories recursively.
- 📦 **Zip Folder Download**: Streaming download of entire S3 folder trees as compressed `.zip` archives.
- 🔗 **Presigned URL Generator**: Generate shareable download links with customizable expiration times (1 hour to 7 days).
- 🎨 **Google Drive UI/UX**: Search filtering, file category filters (Images, Documents, Videos, Audio, Code, Archives), Grid and List views.
- 🐳 **Docker & EC2 Production Ready**: Native Nginx reverse proxying, PM2 process management, and multi-container Docker Compose setup.

## 🛠️ Step-by-Step AWS Setup Guide (S3 + Authentication Options)

### Step 1: Create an S3 Bucket
1. Open the [AWS S3 Console](https://s3.console.aws.amazon.com/).
2. Click **Create bucket**.
3. **Bucket name**: Enter a globally unique name (e.g. `my-company-s3-drive`).
4. **AWS Region**: Select your preferred region (e.g., `ap-south-1` Mumbai).
5. Leave **Block Public Access** settings at defaults (Public access blocked).
6. Click **Create bucket**.

#### Configure S3 CORS Policy (Cross-Origin Resource Sharing):
1. In your bucket page, click the **Permissions** tab.
2. Scroll down to **Cross-origin resource sharing (CORS)** ➔ Click **Edit**.
3. Paste the following CORS configuration:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "POST", "DELETE", "HEAD"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": ["ETag"]
  }
]
```
4. Click **Save changes**.

---

### Step 2: Choose AWS Authentication Method

#### 🌟 Option A: EC2 IAM Role Deployment (RECOMMENDED - Most Secure)
*If deploying on an AWS EC2 instance, you do **NOT** need to create access keys or secret keys! You attach an IAM Role to your EC2 instance instead.*

1. Open the [AWS IAM Console](https://console.aws.amazon.com/iam/) ➔ Click **Roles** ➔ Click **Create role**.
2. **Trusted entity type**: Select **AWS service**.
3. **Use case**: Select **EC2** ➔ Click **Next**.
4. **Add permissions**: Search for `AmazonS3FullAccess` (or attach a custom scoped S3 policy) ➔ Click **Next**.
5. **Role name**: Enter `EC2-S3Drive-Access-Role` ➔ Click **Create role**.
6. **Attach Role to EC2 Instance**:
   - Go to [AWS EC2 Console](https://console.aws.amazon.com/ec2/).
   - Select your EC2 instance ➔ Click **Actions** ➔ **Security** ➔ **Modify IAM role**.
   - Select `EC2-S3Drive-Access-Role` ➔ Click **Update IAM role**.

*Now your EC2 server will automatically authenticate with S3 without needing any secret keys in `.env`!*

---

#### 🔑 Option B: IAM User & Access Keys (Alternative for Local / Non-EC2)
*Use this option if running locally on your PC or deploying on third-party cloud providers (Vercel, Render, DigitalOcean).*

1. Open [AWS IAM Console](https://console.aws.amazon.com/iam/) ➔ Click **Users** ➔ Click **Create user**.
2. **User name**: Enter `s3-drive`.
3. Click **Next** ➔ Select **Attach policies directly** ➔ Search for `AmazonS3FullAccess` ➔ Click **Create user**.
4. Select user `s3-drive` ➔ Click **Security credentials** tab.
5. Scroll to **Access keys** ➔ Click **Create access key** ➔ Select **Application running outside AWS**.
6. Copy your **Access Key ID** and **Secret Access Key** into `.env`.

## 🚀 Quick Start (Local Development)

### 1. Prerequisites
- Node.js `>= 18.x`
- npm `>= 9.x`

### 2. Setup Project
```bash
git clone https://github.com/therahulpatil/S3-Drive.git
cd S3-Drive
npm install
```

### 3. Create Environment File (`.env`)
Create a `.env` file in the root directory:
```env
AWS_BUCKET_NAME=my-company-s3-drive
AWS_REGION=ap-south-1
AWS_ACCESS_KEY_ID=YOUR_AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=YOUR_AWS_SECRET_ACCESS_KEY
PORT=5000
```

### 4. Run Development Servers
```bash
# Terminal 1: Run Express Proxy Backend (Port 5000)
npm run server

# Terminal 2: Run Vite React Frontend (Port 3000)
npm run dev
```

Open **`http://localhost:3000`** in your browser.

## 🌐 Guide 1: Deploy on AWS EC2 (Native Node + Nginx + PM2)

### Step 1: Launch EC2 Instance
1. Open **AWS EC2 Console** ➔ Click **Launch Instance**.
2. Select **Ubuntu 24.04 LTS** or **Ubuntu 22.04 LTS** (`t3.micro` or `t2.micro`).
3. Under **Network settings**, configure Security Group Inbound Rules:
   | Type | Protocol | Port | Source |
   | :--- | :--- | :--- | :--- |
   | SSH | TCP | 22 | My IP / 0.0.0.0/0 |
   | HTTP | TCP | 80 | Anywhere (0.0.0.0/0) |
   | HTTPS | TCP | 443 | Anywhere (0.0.0.0/0) |

### Step 2: SSH into EC2 & Install Node.js & Nginx
```bash
# Update System Packages
sudo apt update && sudo apt upgrade -y

# Install Node.js 20 LTS & Git
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs git nginx

# Install PM2 Process Manager globally
sudo npm install -g pm2
```

### Step 3: Clone Repository & Build Application
```bash
# Clone Repository
git clone https://github.com/therahulpatil/S3-Drive.git
cd S3-Drive

# Install Dependencies
npm install

# Create Production .env
nano .env
```

If using **IAM Role (Recommended Option A)**, `.env` only requires:
```env
AWS_BUCKET_NAME=my-company-s3-drive
AWS_REGION=ap-south-1
PORT=5000
```

Build the React frontend:
```bash
npm run build
```

### Step 4: Start Express Backend with PM2
```bash
# Start backend API server with PM2
pm2 start server.js --name "s3-drive-backend"

# Configure PM2 to start automatically on system reboot
pm2 startup
pm2 save
```

### Step 5: Configure Nginx Reverse Proxy
Edit Nginx site configuration:
```bash
sudo nano /etc/nginx/sites-available/default
```

Replace contents with:
```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    server_name _;

    # Serve Vite React Production Static Files
    root /home/ubuntu/S3-Drive/dist;
    index index.html;

    # Proxy API Requests to Express Server (Port 5000)
    location /api/ {
        proxy_pass http://127.0.0.1:5000/api/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }

    # SPA Client Routing Fallback
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Test and restart Nginx:
```bash
sudo nginx -t
sudo systemctl restart nginx
```

Access your app live at **`http://YOUR_EC2_PUBLIC_IP`**!

## 🧹 Local & Server Environment Teardown Guide

Follow these steps when you want to stop servers, delete containers, or clean up build artifacts:

### 1. Stop & Remove Docker Containers
```bash
# Stop and remove running containers, networks, and volumes
docker compose down -v --remove-orphans

# Deep clean all unused Docker images, containers, and build cache
docker system prune -a --volumes -f
```

### 2. Stop PM2 & Node.js Server Processes
```bash
# Stop and delete PM2 process
pm2 stop s3-drive-backend
pm2 delete s3-drive-backend

# Stop PM2 daemon
pm2 kill
```

### 3. Kill Local Node.js Processes (Port 3000 & 5000)

**Linux / Mac / EC2 Ubuntu:**
```bash
# Kill processes running on ports 3000 and 5000
npx kill-port 3000 5000
```

**Windows PowerShell:**
```powershell
# Stop all running Node.js background processes
Get-Process node -ErrorAction SilentlyContinue | Stop-Process -Force
```

### 4. Remove Build Artifacts & Installed Dependencies
```bash
# Linux / Mac / EC2 Ubuntu:
rm -rf node_modules dist .vite

# Windows PowerShell:
Remove-Item -Path node_modules, dist -Recurse -Force -ErrorAction SilentlyContinue
```

## 💥 Complete AWS Cloud Resource Teardown Guide

Follow these steps if you want to completely destroy all AWS resources created for this project to avoid unexpected charges:

### 1. Delete S3 Bucket & Objects
1. Open the [AWS S3 Console](https://s3.console.aws.amazon.com/).
2. Select your bucket (`my-company-s3-drive`).
3. Click **Empty** ➔ Type `permanently delete` to delete all stored objects and folders.
4. Go back to buckets list, select your bucket ➔ Click **Delete** ➔ Type the bucket name to confirm deletion.

### 2. Terminate EC2 Instance & Elastic IP
1. Open the [AWS EC2 Console](https://console.aws.amazon.com/ec2/).
2. Select your instance ➔ Click **Instance state** ➔ Click **Terminate instance**.
3. If an Elastic IP was allocated, go to **Elastic IPs** ➔ Select IP ➔ Click **Actions** ➔ **Release Elastic IP addresses**.

### 3. Delete Security Groups & Key Pairs
1. In EC2 Console, click **Security Groups** ➔ Select custom group ➔ Click **Actions** ➔ **Delete security group**.
2. Click **Key Pairs** ➔ Select project key pair ➔ Click **Actions** ➔ **Delete**.

### 4. Delete IAM Role & IAM User
1. Open the [AWS IAM Console](https://console.aws.amazon.com/iam/).
2. Click **Roles** ➔ Search for `EC2-S3Drive-Access-Role` ➔ Click **Delete**.
3. Click **Users** ➔ Select user `s3-drive` ➔ Click **Delete**.
